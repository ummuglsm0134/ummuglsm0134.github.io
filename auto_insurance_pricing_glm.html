1. Business Context & Problem Framing
Why this model exists and what it needs to do
In Property & Casualty (P&C) insurance, accurate pricing is the core business problem. Charge too little → the insurer loses money when claims exceed premiums. Charge too much → customers defect to competitors. The goal of a pricing model is to estimate the expected annual cost of insuring each policyholder — their pure premium — so that rates are actuarially fair and financially sustainable.

The industry-standard approach is a two-part GLM:
Part 1 — Frequency Model: How likely is this customer to file a claim? (Poisson GLM)
Part 2 — Severity Model: When they do file, how much does it cost? (Gamma GLM)

Multiplying these two components yields the pure premium — the expected annual loss per unit of exposure.
Core Actuarial Formulas
Pure Premium = Frequency x Severity
Frequency = E[ClaimNb / Exposure] --> Poisson GLM, log link + offset
Severity = E[ClaimAmount | Claim > 0] --> Gamma GLM, log link
GLM link: log(mu) = B0 + B1*X1 + B2*X2 + ... + log(Exposure)
Relativity = exp(Bi) --> multiplicative factor on base rate

3. Frequency Model — Poisson GLM
Modeling expected claim count per unit of exposure
Claim counts are non-negative integers whose variance approximates their mean — the hallmark of a Poisson process. We use a log link function to ensure predicted frequencies are always positive, and include log(Exposure) as a fixed offset (not a fitted parameter) to normalize policies with different coverage durations. A 6-month policy should be evaluated at half-year expected claims, not penalized against annual policies. 
import statsmodels.formula.api as smf
import statsmodels.api as sm

# Feature engineering
df['DrivAge_band'] = pd.cut(df['DrivAge'], bins=[17,24,29,44,64,79],
                     labels=['18-24','25-29','30-44','45-64','65+'])
df['BM_band']      = pd.cut(df['BonusMalus'], bins=[49,80,100,120,229],
                     labels=['<80','80-100','100-120','>120'])
df['LogDensity']   = np.log1p(df['Density'])
df['LogExposure']  = np.log(df['Exposure'])  # becomes the offset

train, test = train_test_split(df, test_size=0.2, random_state=42)

# Poisson GLM -- log link + exposure offset
freq_model = smf.glm(
    formula='ClaimNb ~ C(Area) + VehPower + C(VehAge_band) + C(DrivAge_band) + C(BM_band) + C(VehGas) + LogDensity',
    data=train,
    family=sm.families.Poisson(link=sm.families.links.Log()),
    offset=train['LogExposure']   # fixed offset -- not a fitted coefficient
).fit()

test['freq_pred'] = freq_model.predict(test, offset=test['LogExposure'])

# Relativities: exp(coeff) = multiplicative factor on base rate
relativities = np.exp(freq_model.params).drop('Intercept')

4. Severity Model — Gamma GLM
Modeling claim cost conditional on a claim having occurred
Claim amounts are strictly positive and right-skewed: the mean (€1,427) sits well above the median (€1,152), pulled by a heavy upper tail. The Gamma distribution naturally captures this shape. We use a log link for multiplicative rate factor interpretability — consistent with the frequency model and with actuarial rate-filing conventions.

The severity model is trained only on claim-level rows — not on all policies. Policies with zero claims don't inform how expensive a claim is; they only inform how likely one is (frequency model's job). 
# df_sev: one row per individual claim
# Merge rating factors from the policy table onto each claim row
df_sev_model = df_sev.merge(
    df[['PolicyID','Area','VehPower','VehAge_band',
        'DrivAge_band','BM_band','VehGas','LogDensity']],
    on='PolicyID', how='left'
)

# Gamma GLM -- log link, claim-level data only
sev_model = smf.glm(
    formula='ClaimAmount ~ C(Area) + VehPower + C(VehAge_band) + C(DrivAge_band) + C(BM_band) + C(VehGas) + LogDensity',
    data=df_sev_model,
    family=sm.families.Gamma(link=sm.families.links.Log())
).fit()

test['sev_pred']     = sev_model.predict(test)

# PURE PREMIUM = Frequency x Severity
test['pure_premium'] = test['freq_pred'] * test['sev_pred']

print(f"Mean pure premium: EUR {test['pure_premium'].mean():.2f} / policy-year")

Why not a single Tweedie GLM? A Tweedie combines frequency and severity in one model (valid for zero-inflated continuous losses). 5. Model Validation — Actuarial Metrics
Lorenz curve, Gini coefficient, and lift by risk decile
Standard ML metrics like RMSE are insufficient for pricing model validation. Actuaries use discrimination metrics that assess whether the model correctly ranks policyholders by risk — because a model that orders risk correctly produces fair relative rates even if absolute predictions aren't perfect.

Lorenz Curve: Sort policies by predicted risk (high → low). Plot cumulative % of actual claims captured vs. cumulative % of policies examined. A perfect model captures all high-risk policyholders first — steep curve hugging the top-left. A random model follows the diagonal.

Gini Coefficient: 2 × (area under Lorenz curve − 0.5). Range 0–1; higher = better. This model achieves Gini = 0.1736.

Lift by Decile: Split policies into 10 risk groups by predicted pure premium. A well-calibrated model produces monotonically increasing actual claim rates from D1 (lowest predicted) → D10 (highest predicted). 
def gini_lorenz(actual, predicted):
    # Sort descending: highest predicted risk first
    dv = pd.DataFrame({'actual': actual.values, 'pred': predicted.values})
    dv = dv.sort_values('pred', ascending=False).reset_index(drop=True)
    n  = len(dv)

    dv['cum_pop']  = np.arange(1, n+1) / n            # x-axis: % of policies
    dv['cum_loss'] = dv['actual'].cumsum() / dv['actual'].sum()  # y-axis: % of claims

    x   = np.concatenate([[0], dv['cum_pop'].values])
    y   = np.concatenate([[0], dv['cum_loss'].values])
    auc = np.trapezoid(y, x)
    return 2 * auc - 1, x, y   # returns gini, lorenz_x, lorenz_y

test['had_claim'] = (test['ClaimNb'] > 0).astype(int)
gini, lx, ly    = gini_lorenz(test['had_claim'], test['freq_pred'])
print(f'Gini coefficient: {gini:.4f}')

# Lift by risk decile
test['decile'] = pd.qcut(test['pure_premium'], 10, labels=False) + 1
lift = test.groupby('decile').agg(
    predicted_pp   = ('pure_premium', 'mean'),
    actual_cl_rate = ('had_claim', 'mean')
)

6. Rating Factor Relativities & Business Interpretation
Translating model coefficients into actionable pricing factors
GLM coefficients in a log-link model are log-relativities. Exponentiating them yields the multiplicative factor applied to the base rate. This is directly how actuaries express rate changes: a DrivAge 18–24 relativity of 1.82× means that segment is charged 82% more than the reference driver (30–44), holding all other rating factors constant. This additive-on-log / multiplicative-on-rate structure makes GLMs regulator-friendly — each factor is examinable and defensible independently.

Why this is regulator-friendly: A state insurance department reviewing the rate filing can ask “why does an 18-year-old pay 82% more?” — and the actuary points to the coefficient, its confidence interval, and the underlying loss data. This transparency is not possible with a black-box GBM, which is why GLMs remain the standard for filed rates even where GBMs dominate internal analytics.

7. Model Risk Management (MRM) Considerations
Documentation, independent validation, and ongoing monitoring
In a regulated insurance environment, model development is only half the work. Model Risk Management — per Federal Reserve guidance SR 11-7 — requires that all material models be documented, independently validated, and continuously monitored in production.

Development documentation: Data sources and vintage, feature engineering decisions, distributional assumptions (Poisson/Gamma family choices), known limitations (no telematics, no credit score), and out-of-scope applications.

Independent validation: A separate team re-runs the model on held-out data, challenges rating factor selections, and verifies that relativities are statistically significant and directionally sensible vs. industry priors.

Ongoing monitoring: Track actual-vs-expected (A/E) loss ratios monthly by segment. If A/E diverges >10% in any rating cell, trigger a model review. Re-run Lorenz/Gini metrics on each production scoring cycle to detect drift.

Change management: Any material change to features, data vintage, or model structure requires re-validation and sign-off before deployment.
Production Monitoring KPIs
A/E Ratio = Actual Losses / Expected (Modeled) Losses --> target: 0.95-1.05
Gini drift = |Gini_current - Gini_baseline| > 0.03 --> trigger model review
Lift stability = D10/D1 claim rate ratio should stay stable across monitoring periods
PSI (freq) = Population Stability Index on freq_pred distribution --> >0.20 = retrain

Project Results
Dataset : 60,000 auto insurance policies (freMTPL2-style), 80/20 train-test split
Claim rate : 11.57% of policies filed at least one claim
Mean severity : €1,427 per claim (median €1,152 -- right-skewed, confirms Gamma family choice)

Gini coefficient : 0.1736 (positive discrimination vs. random baseline of 0.000)
Deviance explained : 2.12% (Poisson GLM; claim signals are diffuse across many rating factors)
Top risk factors : Driver age 18-24, dense urban territory (F), poor Bonus-Malus history
This project demonstrates the core actuarial GLM pricing pipeline used in P&C insurance. The two-part structure (Poisson frequency + Gamma severity) reflects industry practice and produces interpretable, regulator-defensible rating factor relativities. The Lorenz/Gini validation framework is the actuarial standard for model discrimination — analogous to AUC/lift in classification, but designed for the insurance loss context.

Extensions for production: incorporate telematics data (mileage, braking events), add geographic territory splines, use LightGBM to discover non-linear interactions then re-encode top interactions into GLM for regulatory filing, implement Tweedie comparison as robustness check, and build automated A/E monitoring dashboard with alerting on drift thresholds.
